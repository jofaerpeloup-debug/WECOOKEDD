### Slice 2 final Collection Detail source correction — 2026-10-12

- The final re-review found that overlapping removals or a refresh could advance the read session and cause a successful removal to be ignored. User-collection removal now takes a synchronous single-mutation lock. Starting a removal invalidates earlier GETs, blocks same-collection refresh/load-more during the mutation, and exposes accessible pending state. A refresh requested during the mutation is served by the successful removal's authoritative refetch, or reissued after a failed removal. A completed mutation is accepted only for the same authenticated owner, collection and focus epoch; an old completion cannot publish into a newly selected scope.
- After successful removal, the visible row is pruned, pagination is invalidated, and page one is fetched again. Failure keeps the row and reports the existing error. Server `pagination.total` counts membership records before unusable recipes are filtered; the user-collection header therefore labels it as **collection entries**. When a total is unavailable, it says **loaded recipes**. The existing header type and position remain unchanged.
